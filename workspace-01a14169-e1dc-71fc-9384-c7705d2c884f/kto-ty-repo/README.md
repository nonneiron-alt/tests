# кто.ты

Русскоязычные AI-квизы в стиле старого интернета. Пользователь придумывает тему, Groq задает 5 вопросов и создает персональный результат с картинкой. Темы сохраняются в общем каталоге, результаты доступны по ссылке.

> **Открытая проблема P0:** владелец сообщает о результатах, не связанных с темой/ответами. Пока не исправлено. Следующему агенту начать с `AGENTS.md` и `docs/AI-RESULTS-P0.md`.

## Стек

- Frontend: vanilla HTML/CSS/JS, локальные фотографии и GIF.
- Основной backend: Cloudflare Workers + D1.
- AI: Groq, модель `openai/gpt-oss-120b`.
- Картинки результата: Wikipedia API, затем локальная тематическая фотография.
- Альтернативный локальный backend: Python standard library + SQLite.

## Быстрый запуск Workers локально

Нужен **Node.js 22+ LTS**. В PowerShell:

```powershell
npm ci
Copy-Item .dev.vars.example .dev.vars
# Впишите ваш ключ в .dev.vars. Этот файл не коммитится.
npm run db:local
npm run dev
```

Откройте URL, который выведет Wrangler (обычно `http://localhost:8787`). Для изменения только верстки ключ не нужен; без ключа AI-шаги вернут понятную ошибку. Локальная D1 хранится в `.wrangler/`, не в облаке.

```powershell
npm run check
npm test
```

Офлайн тесты проверяют API-контракт и передачу темы/ответов, **не реальную семантическую корректность модели**. Для качества оставлены TODO и синтетические кейсы.

## Деплой в Cloudflare

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy.ps1
```

Вход Cloudflare — в браузере, ключ — скрытым вводом. Скрипт подключает/создает D1 `kto-ty-quiz-db`, применяет миграции, загружает сайт и сохраняет ключ как Worker Secret. Данные существующей D1 не удаляет. При наличии нескольких аккаунтов можно указать `-AccountId`; при необходимости `-DatabaseId` с реальным UUID.

Повторный деплой с сохранением серверного ключа:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy.ps1 -KeepSecret
```

Подробности, другие ОС и разовый импорт старой SQLite: `docs/DEPLOY.md`.

## Python-вариант (не Cloudflare)

```powershell
$env:GROQ_API_KEY = 'ваш-новый-ключ'
python server.py
```

Откройте `http://localhost:3000`. База `quizzes.sqlite3` создается автоматически. Python 3.10+, pip-зависимостей нет. Python и Worker имеют отдельные реализации AI-логики: исправление одной не изменяет другую.

## Приватный GitHub

1. Создайте **Private** репозиторий в GitHub. Этот архив сам репозиторий не создает.
2. Распакуйте в новую чистую папку, **не поверх старого установщика с ключом**.
3. В папке выполните:

```powershell
git init
git add .
git diff --cached --stat
git diff --cached
# Убедитесь, что нет настоящих ключей, .dev.vars, базы, install.ps1.
git commit -m "Initial source snapshot and agent handoff"
```

Далее выполните команды добавления remote/push из страницы **вашего** нового GitHub-репозитория. Либо загрузите исходники через web UI, включая скрытые `.gitignore` и `.dev.vars.example` (не сам `.dev.vars`). На GitHub проверьте видимость Private.

В архиве нет `.git`, предыдущих коммитов, ключей и пользовательской базы. Старый автономный `install.ps1` и извлеченный из него `deploy.mjs` содержали ключ — **не копируйте их в этот репозиторий**. Текущий `deploy.mjs` — новая версия без встроенных credentials.

## Ограничения

Это развлечение, не психологическая диагностика. Не собирайте чувствительные данные. Результат виден любому с его ссылкой. Для публичного масштаба нужны модерация, антибот, лимиты запросов и расходов. Разрешения/квоты Cloudflare и доступность Groq не гарантируются репозиторием. Автоматического CI/CD и автопубликации при push нет.

Лицензия исходного кода пока владельцем не выбрана; публичную лицензию автоматически не добавляли.
