## Приоритет P0

Последнее сообщение владельца: **«ии выдает как результат теста полную хрень не связанную с вопросом»**. Это реальная жалоба пользователя, НЕ исправленная в этом архиве. Точного примера темы, пяти ответов и плохого результата пока нет. Не выдавай гипотезы за установленную причину. Сначала воспроизведи и проверь передачу topic/answers, затем качество генерации и семантическую валидацию. Успешный HTTP/JSON тест не означает качественного ответа AI.

## Архитектура и ограничения

- Основная целевая платформа: Cloudflare Workers + D1 (`worker.js`).
- Фронтенд: vanilla JS/CSS/HTML в `static/`.
- `server.py`: отдельный локальный backend SQLite, не вызывается Cloudflare Worker. Логика AI продублирована, может расходиться. Исправление только Python не починит опубликованный Worker.
- Groq: `openai/gpt-oss-120b`. Не заменять модель молча.
- Сохранять ретро-дизайн: старые сайты, гифки, повторяющийся фон, псевдоокна, русский текст.
- Созданные тесты сразу сохраняются в общий каталог; пользователь отвечает на 5 вопросов и получает индивидуальный развернутый результат с картинкой.
- Не удалять существующую облачную базу и не пересоздавать D1 для обхода бага. ID аккаунта, базы и сайт пользователя неизвестны.
- Новый вариант оценки/плана теста может потребовать новой миграции. Не менять уже примененную `0001_schema.sql` для обновления продакшена.

## Секреты и данные

- В этой копии нет ключей, базы с сессиями или старых установщиков.
- В предыдущем чате владелец разрешил вшить настоящий Groq-ключ в автономный PS1. **Такой установщик и извлеченный из него deploy.mjs не переносить в Git.** Даже приватный репозиторий не является хранилищем секретов.
- Для разработки `.dev.vars` (игнорируется), для продакшена Worker Secret `GROQ_API_KEY`.
- Не логировать ключ, Authorization, полные чувствительные ответы. Для диагностики использовать синтетические кейсы или получить согласие на обезличенный пример.

## Рабочий процесс

- Node 22+; `npm ci`, `npm run db:local`, скопировать `.dev.vars.example` в `.dev.vars`, `npm run dev`.
- `npm test` — офлайн API-контракт; три TODO о семантическом качестве намеренно не реализованы.
- `npm run check` — проверка синтаксиса.
- `tests/fixtures/quality-cases.json` — синтетические кейсы, не реальные пользовательские логи.
- Обновлять тесты и документацию вместе с кодом. После исправления P0 приводить конкретные до/после примеры и указывать, была ли проверка на живой модели.
- Не заявлять успешный деплой в аккаунт владельца без фактической проверки. Не создавать репозиторий/публиковать изменения без запроса.
