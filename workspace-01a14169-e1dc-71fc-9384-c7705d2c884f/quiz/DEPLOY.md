# Деплой из PowerShell на Cloudflare

Этот комплект дополняет существующую папку `quiz`. Распакуйте файлы **прямо в неё**, рядом с `server.py`, `quizzes.sqlite3` и папкой `static`. Не создавайте вложенную `quiz/quiz`.

## Что меняется

Cloudflare Workers не запускает этот Python HTTP-сервер и не хранит локальный файл SQLite как обычный диск. Поэтому:

- `worker.js` заменяет серверный API для Cloudflare;
- `static` загружается через Workers Static Assets без изменения фронтенда;
- SQLite переносится в Cloudflare D1;
- ключ Groq хранится в Worker Secret, а не в браузере или конфиге;
- `server.py` остаётся для локального запуска. После переноса локальная SQLite и D1 **не синхронизируются**.

## Первый запуск

1. Установите актуальный Node.js LTS (не ниже 20) с https://nodejs.org/ и откройте новое окно PowerShell.
2. Создайте/подготовьте аккаунт Cloudflare.
3. В папке проекта выполните:

```powershell
cd C:\Users\Administrator\Desktop\quiz
Unblock-File .\deploy.ps1
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\deploy.ps1
```

Изменение ExecutionPolicy действует только для текущего процесса PowerShell. На компьютере с корпоративными ограничениями может действовать более строгая политика.

Скрипт:

1. Запускает Wrangler через `npx --yes wrangler@4` (глобальная установка не нужна).
2. Открывает авторизацию Cloudflare в браузере, если не задан API-токен.
3. Находит или создаёт D1 `kto-ty-quiz-db`.
4. Создаёт `wrangler.jsonc` с реальным ID базы и применяет миграцию.
5. Если есть `quizzes.sqlite3`, экспортирует темы/сессии и импортирует их в D1. Для этого нужен Python с модулем sqlite3. Экспорт читается без изменения исходной базы, временный SQL удаляется после команды импорта. Совпадающие ID не перезаписывают облачные темы и результаты; счётчик прохождений берётся по максимуму, а не суммируется.
6. Загружает Worker и содержимое `static`.
7. Просит ввести **новый** Groq-ключ скрытым вводом и сохраняет его как секрет `GROQ_API_KEY`.

Wrangler покажет реальный адрес вида `https://kto-ty-quiz.<ваш-поддомен>.workers.dev`. При первом использовании Workers Cloudflare может попросить выбрать workers.dev-поддомен. До сохранения секрета статические страницы доступны, но AI не работает.

**Не используйте опубликованный ранее ключ — отзовите его и создайте новый.** Ключ не передаётся параметром командной строки и не сохраняется в файлах. Модель: `openai/gpt-oss-120b`.

## Последующие обновления

```powershell
.\deploy.ps1 -SkipLogin -KeepSecret -SkipImport
```

`-KeepSecret` проверяет наличие существующего GROQ_API_KEY. Чтобы сменить ключ, уберите этот флаг.

Если новый сайт нужен без переноса старой базы:

```powershell
.\deploy.ps1 -SkipImport
```

Для другого имени сайта:

```powershell
.\deploy.ps1 -Name my-retro-quiz
# При повторном запуске используйте то же имя:
.\deploy.ps1 -Name my-retro-quiz -SkipLogin -KeepSecret -SkipImport
```

Не меняйте `-Name`/`-DatabaseName` между обновлениями одного сайта: иначе можно создать другой Worker или другую базу. Удаление/перезапись таблиц скриптом не выполняется. Не редактируйте уже применённую миграцию — изменения схемы оформляйте новым SQL-файлом в `migrations`.

## Несколько аккаунтов Cloudflare / API-токен

Выберите account ID в панели Cloudflare и передайте его явно:

```powershell
.\deploy.ps1 -AccountId 'ВАШ_ACCOUNT_ID'
```

Для автоматизации можно заранее задать `CLOUDFLARE_API_TOKEN` в окружении и использовать `-SkipLogin`. Права токена должны покрывать Workers Scripts, D1 и необходимые чтения аккаунта. Не вставляйте токен в файлы проекта и не публикуйте его.

## Собственный домен

После успешного деплоя откройте Cloudflare Dashboard → Workers & Pages → ваш Worker → Settings → Domains & Routes → Add → Custom Domain. Для домена, подключённого к Cloudflare, панель подскажет настройку DNS. Это отдельный шаг; скрипт публикует сайт на workers.dev.

## Что проверено / ограничения

Проверены сборка Wrangler (`deploy --dry-run`), запуск Worker в локальном runtime, миграция D1, каталог, создание темы, валидация и импорт SQLite. Деплой в ваш аккаунт и установка секрета выполняются у вас — здесь доступа к аккаунту нет.

AI использует внешний Groq API и его лимиты. Перед публикацией для большой аудитории настройте защиту от злоупотреблений: rate limiting/Turnstile, лимиты расходов Groq и модерацию тем. Лимиты Workers/D1 зависят от тарифа аккаунта. Аккаунтов пользователей нет; сохранённый результат доступен любому, у кого есть ссылка. Не собирайте чувствительные данные.

`deploy.ps1` написан для Windows PowerShell 5.1+ / PowerShell 7; реальная авторизация и деплой в Windows требуют вашей проверки. Если шаг завершился ошибкой, исправьте причину и повторите запуск с теми же именами.

## Если скрипт не определил ID D1

Исправленная версия разбирает вложенные JSON-массивы PowerShell 5.1 и поля `uuid`, `database_id`, `id`. Для ручного указания существующей базы:

```powershell
npx.cmd --yes wrangler@4 d1 list --json
```

Скопируйте фактический UUID записи с именем `kto-ty-quiz-db`, затем передайте его параметром `-DatabaseId` при запуске `deploy.ps1 -SkipLogin`. Не придумывайте ID и не используйте ID аккаунта вместо ID базы. При явном `-DatabaseId` скрипт не создаёт другую базу. Для нестандартного имени также передайте `-DatabaseName`.
